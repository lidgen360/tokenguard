# Changelog

## 0.7.1 — 2026-11-12

- Контекстный хук просит согласие **кнопками**: маркер `[tokenguard-context]` теперь
  инструктирует модель вызвать `ask_user_question` с вариантами «Сжать сейчас (Recommended)»
  и «Позже». В Web GUI это карточка с кнопками; после «Сжать» выполняется
  `tokenguard chats compact <id> --keep-last 8`.
- Guard-правило дополнено: согласие на сжатие спрашивается через `ask_user_question`, не текстом.
- Тесты: 87.

## 0.7.0 — 2026-11-10

- **Контекстный хук `contextHook`** (по умолчанию выключен): когда последний запрос
  превышает `contextThreshold` (по умолчанию 350k), в контекст добавляется короткое
  напоминание с цифрами и вопросом «сжать?» — не чаще `contextHookCooldownMinutes`
  (45 мин) на сессию.
- Хук читает только текущую сессию по `transcript_path`/id (~0.16 с), а не сканирует
  все чаты; ничего не создаёт и не удаляет.
- `doctor` и `guard status` показывают состояние контекстного хука.
- Тесты: 87.

## 0.6.0 — 2026-11-10

- **`tokenguard chats pressure`** — давление контекста: последний запрос, максимум,
  накопительная сумма, порог (флаг `--threshold` или `contextThreshold` в `config.json`)
  и оценка экономии на 100 запросов. Наглядно показывает, что «200M токенов» — это
  накопленная сумма за сотни запросов, а не размер контекста.
- **`tokenguard chats compact --auto`** — выбрать самую тяжёлую сессию выше порога
  и сжать её в конспект (маскировка секретов, чат не создаётся автоматически).
- `parseTokenCount` — разбор порогов вида `350k`, `1.2M`, `500000`.
- Тесты: 77.

## 0.5.0 — 2026-11-10

- **`tokenguard report --html <file>`** — самодостаточный HTML-отчёт: inline CSS и SVG-графики,
  итоги, топ-сессии и инструменты, маскот; без внешних запросов и скриптов.
- **`tokenguard attachments list|clean`** — вложения DSH: объекты, размер, осиротевшие;
  очистка только неиспользуемых объектов старше порога (`--apply`), при нечитаемых
  сессиях удаление отменяется.
- **`tokenguard mcp verify [<server>|--all]`** — живая проверка MCP: stdio и http(s),
  `initialize` + `tools/list`, число инструментов, латентность; exit 1 при ошибке.
- **`tokenguard completions bash|zsh|fish`** — автодополнение команд и подкоманд.
- **`tokenguard init`** — первичная настройка: каталог данных, guard-правило в AGENTS.md,
  хук DSH (если профиль готов), подсказка по автозапуску; `--apply` для записи.
- Тесты: 73; macOS-CI — по расписанию и вручную.

## 0.4.0 — 2026-11-10

- **`tokenguard doctor`** — самодиагностика установки: Node.js, каталог данных и права,
  бэкапы, реестр артефактов, найденные харнессы, MCP-конфиги (ленивые и без вызовов),
  lazy-прокси, хук DSH, автозапуск, `config.json`, свободное место.
  `--json` для автоматизации, `--strict` — код 1 при предупреждениях,
  `--fix` — только безопасные исправления: создать каталоги, выставить права 700,
  отметить удалёнными записи реестра с пропавшими файлами.
- Тесты: 42 (интеграционные сценарии doctor на изолированном HOME).

## 0.3.5 — 2026-11-10

- Кроссплатформенность: Windows/Linux — пути Claude Desktop по ОС, `mcp watch`
  (`fs.watch` + polling, `--once`), `autostart print` для launchd/systemd/schtasks.
- CI: GitHub Actions matrix (`ubuntu-latest`, `windows-latest`, `macos-latest`) +
  Docker smoke-тест; `node --test` вместо `node --test test/` (Node 22 не находил тесты).

- README: инструкции без локальных путей, установка через `git clone`.

## 0.3.4 — 2026-11-08

- **Хук дрейфа можно выключить без перезапуска DSH**: `{"driftHook": false}` в
  `~/.tokenguard/config.json` или `TOKENGUARD_DRIFT_HOOK=0`. Хук — короткоживущий процесс и читает
  конфиг на каждом запросе, так что следующий промпт уже приходит без `[tokenguard-drift]`.
- **Guard-правило больше не требует предлагать новый чат**: маркер — не более чем информация;
  `chats drift`/`digest`/`compact` остаются ручными командами. `guard install` пишет новое правило,
  `guard status` показывает состояние хука.
- Тесты: 31 (`driftHookDisabled`, mute-сценарии, битый конфиг не ломает хук).

## 0.3.3 — 2026-11-08

- **Автоматический новый чат.** `bin/tokenguard-dsh-new-chat.js` управляет живой вкладкой Safari
  через AppleScript: находит DSH GUI, нажимает «Новая сессия», вставляет перенос и отправляет первым
  сообщением. CLI не нужен, логин и вкладка пользователя переиспользуются.
- Guard-правило теперь требует: маркер `[tokenguard-drift]` → предупреждение + интерактивный вопрос
  «Создать новый чат с переносом контекста?» (Да/Нет) → при Да обновить digest/compact и запустить
  скрипт автоматически.
- Проверено вживую: из чата «OpenRouter Explorer Free» скрипт создал сессию
  «Продолжение OpenRouter Explorer Free» и отправил в неё перенос; вкладка не перезагружалась.
- Тесты: 29 (скрипт проверяется `--dry-run`).

## 0.3.2 — 2026-11-08

- **Хук для DSH**: `bin/tokenguard-dsh-hook.js` — UserPromptSubmit-хук, который на каждом запросе
  запускает `chats drift` и вкладывает в контекст модели маркер `[tokenguard-drift]` с готовым
  предупреждением. Подключается через `@deepseek-ai/dsh-hooks-claude-code` и `hooks.json`; агент
  больше не может «забыть» проверить дрейф — сообщение приходит вместе с запросом.
- Модуль `src/hooks/dsh-user-prompt.js`: `buildDriftContext`, `defaultExec`, `hookOutput` + 4 теста.
- Guard-правило ссылается на маркер и требует выводить предупреждение первым блоком ответа.
- Тесты: 29.

## 0.3.1 — 2026-11-08

- Guard-правило больше не требует бюджет: лимиты не используются, `budget` из правила убран.
- В правиле теперь явное требование к агенту: при дрейфе темы первым блоком ответа выводить
  `⚠️ tokenguard: смена темы (N) — создать новый чат?` и предлагать `chats digest`.
- `guard check` печатает заметный итог «создать новый чат?» вместо мягкой рекомендации.
- Удалён `~/.tokenguard/budget.json` у пользователя (бэкап в `~/.tokenguard/backups`), лимиты отключены.
